# 0.2.79：代理握手卡住时的连接回收

- **上游连接建立后立即登记**：中继到代理的连接此前在握手完成后才进入回收表——代理迟迟不回复握手时，`close()` 找不到这条连接。现连接建立（含 TLS）即登记，`close()` 必定可达。
- **握手限时**：TCP/TLS 连接与协议握手（SOCKS5 greeting/认证/CONNECT、HTTP CONNECT 应答）各有 15 秒上限，到点即释放上游连接并向浏览器返回失败，不再无限等待。
- **统一释放**：握手失败、超时、任务取消或中继关闭都会关闭并注销上游连接；新增"握手卡住时 close 可达"与"握手超时自动释放"两项回归测试。
- 回归：离线 596 项通过。

# 0.2.78：中继凭据泄露修复与启动失败回收

- **SOCKS5 隧道不再携带代理凭据**（高优先级）：SOCKS5 认证只在握手阶段完成；此后隧道内的字节直达目标网站，中继不再向其中注入 `Proxy-Authorization`，并且会剥离浏览器请求中可能携带的代理认证头。HTTP/HTTPS 上游代理的凭据注入行为不变（那些凭据本就属于代理）。已添加"凭据不得到达目标端"的专项回归断言。
- **浏览器启动失败时回收中继**：中继先于浏览器启动；此前若 `spawn()` 本身失败，中继监听会遗留。现启动、附加整体包进回收路径，任一步失败都会终止浏览器进程（如已启动）并关闭中继。图片与视频两条链路均已修复。
- **清理调试输出**：移除中继握手与实例状态的临时打印；诊断信息仅经脱敏后的任务执行记录提供。
- 回归：离线 594 项通过（新增 SOCKS5 凭据剥离断言、隧道剥离用例）。

# 0.2.77：中继多协议支持与全量回收、视频重定位上限

- **中继支持三种上游协议**：本地代理中继此前一律按 HTTP 上游转发，`https://`（TLS 到代理）与 `socks5://`（含用户名密码认证握手）的上游会连接失败。现按代理地址的协议分别实现：http 透传、https 建立 TLS 后发 CONNECT、socks5 完整握手（ greeting/认证子协商/CONNECT，目标走域名由代理解析）。
- **中继关闭即全量回收**：`close()` 除停止监听外，同时关闭所有活动隧道连接（浏览器侧与上游侧），不再出现"监听停了但既有连接仍可继续传数据"的情况；浏览器启动或 CDP 连接失败时，已启动的浏览器进程与中继也会立即回收。
- **视频候选核验加单候选等待上限**：重定位循环中每个候选的详情核验最多等待 20 秒（`candidate_verify_wait`），到点即返回图库尝试下一条新素材，不再依赖"目标绑定已捕获"这一前提，避免停在错误详情页等到总超时。
- 回归：离线 593 项通过；新增中继双协议凭据注入、close 回收、详情页快速失败/无绑定时等待等专项测试。

# 0.2.73：人工验证即撤池与集中通知

自动生成任务遇到登录或人工验证挑战时，不再弹窗并原地等待本人（旧模式最长等 180 秒、阻塞整个队列），改为"**账号立即撤池、任务让路、集中通知**"：

- **提交前撞验证**（生成尚未发出，不可能扣积分）：该账号立即标记"需人工处理"并从执行池撤下，任务按"未提交生成"结束；若队列还有其他可用账号，自动调度继续用其他账号，自动重试的换号逻辑照常生效。
- **提交后撞验证**（生成请求已发出，积分状态未知）：任务不强行改判，按原有超时/待核对链路处理；该账号同样立即撤池。
- **集中通知**：控制台所有页面顶部显示"⚠ N 个账号需要人工处理（已暂停调度）"横幅，点击"打开 Flow 处理"在专用浏览器中由本人完成登录或验证。
- **自动回池**：账号后台自检（身份+积分只读核验）一旦干净通过，标记自动清除、账号恢复调度，无需手动操作。
- 检测到挑战但账号身份按钮同时可见的瞬时状态按误报处理，继续观察不判死；"账号准备/检查页面"类人工流程保持原有可见窗口行为。

该模式不改变提交保护（严格单次、失败不自动重试）、不改变积分对账；被撤下账号在自检通过前不会被任何任务选中。

# 0.2.72：代理保存规范化与视频关联收紧

- **代理地址保存时统一补齐协议**：输入 `host:port`（无协议前缀）的代理，保存时自动按 `http://host:port` 规范化并写库；此前只在校验时补齐，导致积分查询等网络客户端报"代理协议未知"。读取侧同时兼容修复前已保存的旧条目。另随附 `httpx[socks]` 依赖，socks5 代理的网络客户端查询现已可用。

# 0.2.71：账号代理出口绑定

新增"账号 ↔ IP 绑定"：在"账号管理 → 代理出口"添加代理（格式 `http://用户:密码@主机:端口` 或 `socks5://主机:端口`），每个账号固定使用一个专属代理出口，消除多个账号共用本机 IP 的关联特征。未绑定的账号在首次任务时自动分配当前绑定数最少的代理并持久保存；界面提供"测试"（连通性与延迟）、"更换出口"（换到使用最少的其他代理）和"解绑"。留空（不添加代理）时行为与从前完全一致。

代理覆盖范围：生成任务的专用浏览器（Playwright 代理参数）、账号准备与检查浏览器、手动"打开 Flow"的专用窗口、后台积分/身份只读查询、报价核验。凭据只保存在本机数据库，网页与管理接口只显示打码形式（`http://user:***@host:port`）。删除账号记录时同步清除其绑定。

边界与提示：
- **建议使用住宅 / ISP 代理**。机房 IP 的代理通常反而更容易触发 Google 风控；代理质量决定效果。
- **代理地区必须是 Flow 支持开放的地区**（如美国、日本、新加坡、欧洲多数国家）；中国大陆与香港不可用，美国节点最稳妥。代理地区应与账号可访问 Flow 的地区一致并长期固定。
- **同账号的出口必须稳定**。程序按账号粘性绑定，不做同账号每次任务轮换 IP——账号 IP 频繁跳变本身是风控信号。
- 带用户名密码的代理在手动打开的专用 Chrome 窗口会弹一次凭据输入框（Chromium 限制）；建议使用 IP 白名单认证的代理。生成任务与后台查询由程序自动携带凭据。
- 原生 Go 引擎桥接链路仍使用 `FLOW_PROXY` / 系统代理（进程级环境无法按账号区分）；官方网页生成链路已完整覆盖。
- 更换出口后 Google 可能要求该账号重新登录或人工验证，属正常现象；请本人完成。
- 代理不改变提交频率、并发上限和调度策略；代理故障在界面标红提示，程序不会自动更换。

- **任务最小间隔**：相邻两次任务派发的最小间隔默认不限制（0 秒），可在"总览 → 生成并发"调整为 0～600 秒；设置后间隔含 1~1.5 倍随机抖动。运行中任务不受影响。

「后台自动检测」开关保存在本机，重启后沿用；关闭后当前一轮可完成，后续不再自动检测，
仍可手动立即检测。网络失败会显示原因并在下一轮再查询；登录失效、账号身份不符或会话未连接完整时，
明确提示需要本人处理，不把旧积分显示成新的成功结果。后台无法代替本人完成 Google 登录或人工验证。

## 一键准备账号（0.2.10）

需要重新登录或同步时，在「创建任务」「任务管理」或「账号管理」点击 **打开并准备全部账号**，
程序按顺序逐个打开本地账号的 Flow、等待该账号真实同步、核对身份并读取积分，
不会并行切换账号。界面显示总进度和每个账号的结果；单个账号失败后继续检查其他账号，
缺少浏览器连接的账号单独标记为「未检查」，不会冒充检查通过。可点击「停止后续检查」，
当前账号结束后不再打开后续账号。每个账号最多等待 90 秒扩展同步，超时后提示本人处理。

只需重新连接一个账号时，选择账号后点击 **打开并准备所选账号**。
未选择账号时使用第一个可打开的有效本地账号，
并在创建表单中选中该账号，避免准备一个账号却提交到另一个账号。

本操作不创建生成任务、不自动重试失败任务、不提交验证码挑战、不消耗生成积分。
只有明确收到此账号的完整同步记录并通过真实身份和积分查询，才显示检查通过。
打开窗口、监听端口或历史积分均不能替代这些证据。存在排队/生成任务时不会重启桥接。
若 Google 要求重新登录、人工验证或首次手动启用普通 Chrome 扩展，仍需本人在打开的窗口完成；
新会话保存后后台会自动核对身份和积分；也可再点「打开并准备所选账号」。检查通过只表示检查时会话可读取，不保证平台解除生成风控。

## 结论与架构

管理后台位于 `web/`（React + TypeScript）。构建后的页面由原 FastAPI 进程在
`/console/` 提供；新接口位于 `/console/api/`。现有 CLI、`/api/v1/*`、OpenAI
兼容接口、MCP 入口和 Windows Go 引擎保持原路径与参数。后台队列只负责串行
调用 `FlowEngine`。账号资料和余额另外使用同一 Flow 只读 RPC 校验，生成仍由原引擎执行。

| 功能 | 现状 | 第一版处理 |
| --- | --- | --- |
| 文生视频、图生视频、图片生成 | Windows 引擎已有 | 通过真实 `FlowEngine` 提交任务 |
| 账号文件、余额、生成历史 | `cookies/` 与 `data/flow.db` 已有 | 只读概览；手动余额刷新调用引擎 |
| 指定账号 | 引擎支持 `--cookies` | 服务端把所选账号 ID 映射为本地文件路径 |
| 任务队列 | 上游 REST 为同步调用 | 新增单进程、单工作者持久队列 |
| 排队任务取消 | 上游不支持运行中取消 | 仅取消未开始的任务 |
| 失败重试 | 上游没有安全重试判定 | 人工核对后再次确认，创建新任务 |
| 素材 | 引擎写入 `output/` | 本地预览、文件名搜索、分类、下载 |
| 多账号并发 | 引擎有 `--all`，但 README 提醒账号冲突 | 后台不启用并发或 `--all` |
| 自动账号调度 | 引擎默认选最新会话文件 | 可选择轮流使用、积分最多优先、积分最少优先，串行执行 |

**暂不支持：**运行中取消、稳定的多账号并发、云端管理、远程节点、浏览器内
重新登录 Google、精确会话有效性判断、图片批量变体。Windows 引擎帮助信息
明确提示图片 `--count` 目前只兑现 1 张，后台每次图片任务固定 1 张。

后台“自动调度”支持轮流使用、积分最多优先、积分最少优先。依据缓存积分筛选
活跃且有完整会话的账号；视频按当前引擎的时长、画质和数量估算筛选足够的余额。
没有符合条件的记录时停止并提示刷新，不回退盲选。指定账号优先于策略。
策略选择初始会话，不是扣费上限；同一 Google 会话内的账号切换仍由底层引擎决定。
视频模型默认 Omni 1.1 Flash（`omni_flash`）；0.2.39 起增加 Veo 3.1 Lite / Fast / Quality 选择。Veo 使用官方网页链路，原生 CLI 保留原模型及参数链路。
调度不会自动探测上游，也不会同时使用多个账号。账号状态“本地已保存”仅表示
会话文件存在；手动刷新余额是一次上游查询，不能保证后续生成一定成功。

### 发布签名

公开分发时，需要先取得受信任证书颁发机构签发的 Windows 代码签名证书，

签名不会保证新版程序立刻获得 Windows SmartScreen 的信誉。

## 同电脑与局域网 API 调用

完整的请求字段、返回字段、接口清单及 PowerShell/Python 示例见
[接口接入说明](INTEGRATION_API.md)，也可在后台左侧点击“接口接入”。

同电脑的 PowerShell 可以直接读本机接口；以下调用不消耗积分：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8001/api/v1/balance'
Invoke-RestMethod 'http://127.0.0.1:8001/console/api/jobs'
```

原项目 REST 接口和 MCP 入口保持原有调用方式。本机 REST 接口没有密钥，务必保持
`127.0.0.1` 监听，不能把原服务直接改为 `0.0.0.0`。

同局域网调用时，在本机双击仓库根目录的 `Start-FlowConsoleLan.cmd`（需要已构建
EXE）；或者在 PowerShell 运行 `./dist/FlowAgentConsole.exe --lan`。这会同时启动
本机页面 `127.0.0.1:8001` 与**仅含必要接口**的局域网服务 `0.0.0.0:8002`。
密钥首次自动生成于 `flow-agent/data/lan_api_key.txt`；若 EXE 已移出仓库，则位于
`%LOCALAPPDATA%/FlowAgentConsole/flow-agent/data/lan_api_key.txt`。该文件不要分享给
不需要调用 API 的人，也不要上传到 GitHub。Windows 防火墙如弹出提示，只允许
“专用网络”；其他电脑访问前，需允许 TCP 8002 入站，限定专用网络，勿做路由器端口
转发。当前电脑的局域网 IPv4 可用 `ipconfig` 查看。

本机管理页面左侧点击 **接口接入**，在“局域网 API 密钥设置”里可以直接查看地址、
复制密钥到本机剪贴板，或在二次确认后重新生成密钥。网页不会显示密钥内容。
重新生成后旧密钥立即失效，接入项目需要更新配置；已有任务不会因此重新提交。

在另一台 Windows 电脑的 PowerShell 中执行（把地址换成本机的局域网 IPv4）：

```powershell
$key = Read-Host '输入本机密钥文件中的 API 密钥'
$headers = @{ Authorization = "Bearer $key" }
Invoke-RestMethod 'http://192.168.101.7:8002/api/v1/balance' -Headers $headers
Invoke-RestMethod 'http://192.168.101.7:8002/api/v1/jobs' -Headers $headers
```

提交生成任务会消耗积分，API 额外要求 `X-Flow-Allow-Charge: yes`；任务仍在本机
单队列串行处理。例子（仅在确实要生成时执行）：

```powershell
$headers['X-Flow-Allow-Charge'] = 'yes'
$body = @{ kind = 'video'; prompt = '日出时的海面'; aspect = '16:9';
           duration = '8s'; quality = '720p' } | ConvertTo-Json
$job = Invoke-RestMethod 'http://192.168.101.7:8002/api/v1/jobs' `
    -Method Post -Headers $headers -ContentType 'application/json' -Body $body
Invoke-RestMethod "http://192.168.101.7:8002/api/v1/jobs/$($job.id)" -Headers $headers
```

可用的局域网路径：`GET /api/v1/health`、`GET /api/v1/balance`（读取缓存）、
`GET/POST /api/v1/jobs`、`GET /api/v1/jobs/{id}`、`GET /api/v1/media`、
`GET /api/v1/media/{文件名}`、`POST /api/v1/uploads/image`。图生视频先上传图片，
再把返回的 `image_id` 作为任务 `start_image_id`。局域网 API 不开放管理页面、
账号登录、Cookie、Token 或原版无鉴权 REST 路由。HTTP 密钥在局域网内传输未加密；
仅在可信任的家庭或办公专用网络使用，需要跨网络访问时应另配 VPN/HTTPS。

## 连接 Google Flow 账号

在后台点击左侧“账号管理” → “连接 Flow 账号”。后台会启动本机 bridge，打开
一个带本项目扩展的**专用 Chrome for Testing 窗口**，并进入 Google Flow。首次
运行脚本会在需要时自动安装该浏览器。你只需在该窗口
完成自己的 Google 登录；无需手动安装扩展或复制路径。账号列表每 5 秒自动刷新；
首次登录后如果扩展尚未保存会话，后台会自动重连自己启动的 bridge 以触发同步；
有排队或运行中的任务时不会重连。账号出现后，页面提示“已保存到本机”。
出现新账号后，点击“刷新积分”验证上游余额。再次添加账号时，后台会使用另一
专用浏览器配置文件，以保持登录隔离。专用配置文件位于
`flow-agent/data/flow_browser_profile_<序号>/`，包含敏感登录数据，请勿上传。
页面不会接收 Google 密码，也不会显示 Cookie 或 Token。
0.2.5 新增账号自身的只读资料查询：优先显示 Flow 返回的真实名称和邮箱，专用浏览器资料作为后备。
新保存或变化的会话自动查询；已保存资料跨重启保留，不按浏览器顺序猜测对应关系。
普通 Chrome 的账号在邮箱与唯一浏览器资料匹配时也可直接“打开 Flow”。不完整会话显示“未完成连接的账号”。
积分来自当前账号的 `nzlxg` RPC，并附查询时间；`o30O0e` 仅查询名称和邮箱。
此路径修复了部分引擎中“表格显示未读取，但数据库已读到余额”的编号不匹配问题。
每次结果绑定该会话的内容摘要，会话变化或查询失败时不会显示旧余额。
积分显示“未读取”不能当成 0。引擎注册与资料校验各有最多 45 秒查询预算；可点击账号旁的“打开 Flow”，保持 Flow 页面打开，确认扩展
已连接后可重试。只有引擎实际返回完整积分时才记录“最近一次成功读取时间”。
如果 Windows 使用系统代理访问 Google，后台会自动把 HTTPS 代理传给 Flow 引擎；
已设置的 `FLOW_PROXY` 优先。这样浏览器和引擎会使用同一网络出口。

0.2.2 修复了账号文件编号与引擎身份编号不同造成的积分缺失，以及旧数据库数字被误当作实时积分。后台依据本次引擎查询

只有可用账号的余额实际更新后，才记录成功读取时间；未对应当前会话的历史数据保留

## 使用与验证边界

“创建任务”可选择 16:9 或 9:16 视频、时长、画质、账号；图生视频可上传
JPG/PNG/WebP 或选取素材库图片。后台只串行调用 Windows 引擎。任务开始后不能
取消；服务重启时，原本排队或运行中的任务标为“结果待核查”，不会自动重新提交。
重试前先检查素材库、Flow 历史和积分，避免重复计费。

“任务管理”中的 Flow 引擎历史支持按任务/账号 ID、类型、状态查询与分页。浏览器
跨域请求默认只允许本机页面和本机开发端口；CLI、MCP 与不带浏览器 Origin 的
REST 客户端继续使用原入口。

开发验证：

```powershell
cd .\flow-agent
.\.venv\Scripts\python.exe -m pytest -q --basetemp .\.pytest-tmp
cd ..\web
npm.cmd ci
npm.cmd run build
```

这些离线测试不会调用 Google，也不能证明真实账号登录、积分查询或付费生成成功。

## 0.2.7 参考素材入口

在“创建任务 → 视频模式”中选择：

- **首尾帧**：上传首帧，可再上传尾帧，支持预览、替换、移除和素材库选择。
- **参考图**：一次选择多张人物、物品、场景图。后台不额外限制参考图张数，每次生成 1 条；实际可用数量由 Flow 决定，多图真实生成尚待验证。此引擎路径不能指定比例或画质，界面显示“由 Flow 决定”。
- **视频编辑**：上传待修改的原视频，配合提示词编辑。本版接入限 MP4、10 秒以内、100 MB 以内；不指定时长、画质或比例。当前引擎接入不支持把视频当动作参考与参考图混合生成。

图片支持 JPG/PNG/WebP，每张 20 MB 以内。上传和预览只发生在本机；确认提交任务后才把素材交给 Flow。移除只取消本次素材引用，不删除本地文件。接口接入页面同步提供新字段和上传协议。

MP4 校验检查容器、视频轨道和时长，不等于验证所有编码均可解码。本地上传、队列参数和离线引擎调用测试不代表 Google 实际成片成功；实际生成/编辑会消耗积分，需要另行明确授权验证。

构建机可安装 Inno Setup 7 到 `build/tools/InnoSetup7`，构建脚本会优先查找该目录；也可传 `-CompilerPath "完整的 ISCC.exe 路径"`。仅编译安装包需要这个工具，普通安装使用不需要。


## 0.2.22 后台隐藏与自动关闭

Windows 后台任务使用真实的专用 Chrome，窗口默认隐藏，不再只最小化。需要登录或人工验证时，窗口自动显示，后台提示等待本人处理；完成验证后恢复隐藏。程序不会代填密码或处理验证码。图片 2.1 等待本人操作最长 180 秒，旧引擎连接等待最长 90 秒。

成功、失败、超时或取消后的清理都会关闭本次专用浏览器。清理只匹配本次启动的专用浏览器路径、账号资料目录和进程创建时间；已有普通 Chrome 不受影响。专用资料已被其他窗口占用时停止任务，请先关闭该专用窗口，程序不接管已有窗口。

“准备账号”和手动“打开 Flow”仍显示窗口，方便本人登录；“账号准备完成后自动关闭”开关仅控制账号准备页面，不取消自动任务结束时的清理。CLI、REST、MCP 原入口保留；本项控制作用于管理后台启动的浏览器。

“检查图片页面（不生成）”会阻止生成、放大等收费请求，用于验证账号身份、2.1 模型参数、隐藏状态和退出状态。通过检查不等于真实生成成功。本轮只进行无积分验证；真实后台生成、结果归属、任务成功和下载的完整收费验收尚未重新执行。


## 0.2.31 自动重试

创建任务页可启用失败后最多重试3次，连同首次最多4次，间隔10、30、60秒。同一任务记录每次尝试，沿用原账号和参数，成功即停止。已知原结果编号时先恢复下载；未识别结果且已经提交的失败须单独勾选重复扣费授权才重新生成。平台拒绝、账号权限、登录、积分不足、人工验证等问题停止自动重试。等待重试的任务可以取消；已有历史失败任务不自动重跑，服务重启不自动补跑。接口使用 auto_retry_limit 和 retry_uncertain，详见接口接入说明。离线回归不代表 Google 真实重试生成已验收。


## 0.2.40 开机启动与账号提醒

右上角“开机启动”开关控制当前 Windows 用户登录后静默启动到托盘，不自动打开窗口。默认不开启；关闭开关即取消。仅安装后的 Windows EXE 可设置，不会把开发环境 Python 注册为启动项。卸载时清除此应用的启动项。

账号后台检测默认只显示异常与待处理账号，正常账号收起，通过“查看全部账号状态”展开。待登录账号可直接点击“重新连接”；原批量准备、浏览器检查和准备完成自动关页设置合并到“连接与验证工具”中。运行中的准备流程和需处理结果会自动展开。检测通过不代表生成风控解除。


## 0.2.41 页面职责整理

账号后台检测、连接准备和批量准备只在“账号管理”显示；图片与视频只读验证检查集中在账号管理的“高级验证工具（不生成）”。任务管理保留并发、重试策略、任务列表和引擎历史，创建页保留生成参数和与当前参数相关的只读检查。不改变后台检测服务，切换页面仍继续执行。


## 0.2.42 默认无头验证

账号管理的“连接与验证工具”新增“默认使用无头浏览器验证”，默认开启。所选或全部账号准备、图片页面检查、视频页面检查以及浏览器检查均走无头只读验证；成功、失败、取消和超时均执行浏览器退出清理。无头验证不生成素材、不自动处理人工验证，发现登录或人工验证需求即关闭并提示本人处理。后台监测继续优先使用无需浏览器的身份与积分查询。

账号列表“打开 Flow”和新增账号入口仍明确显示浏览器，方便本人登录和检查。这些手动打开的窗口不被自动验证清理；请检查完自行关闭。生成任务保留已验证的隐藏真实浏览器方式，本次选项只控制验证，未更改生成提交链路。


### 0.2.44 账号身份同步修复

自动无头检测在核验网页邮箱后，从本次浏览器取得当前会话，再读取真实身份和积分。仅当邮箱与原记录一致且本地会话未被其他操作更改时保存更新；网络失败、错账号不覆盖旧会话。手动“打开 Flow”仍显示窗口，自动检测默认无头并在结束时关闭。


## 0.2.49 启动自查与服务就绪

打开客户端后先检查数据库、数据目录、素材目录、运行引擎（只执行帮助命令）、浏览器和 MCP 组件、管理页面及扩展文件。启动前检查指定端口能否监听；被占用时只提示，不终止占用程序。

基础检查通过后开放生成入口并启动账号后台检测；不等待全部账号通过。没有账号或个别账号需要登录，不会阻止管理后台启动。启动自查中或严重故障时，本机及局域网任务提交、图片/视频生成和视频编辑返回 HTTP 503，不创建生成任务。页面显示检查进度和故障处理方法；通过后的明细默认收起，可点击“服务已就绪”展开。

账号后台检测沿用无头同步失效会话、确需登录或验证才显示窗口的机制。启动自查不执行真实生成、不消耗积分，也不能证明第三方平台一定允许生成。修复缺失组件、磁盘或权限问题后，完全退出并重新启动客户端即可重新自查。
