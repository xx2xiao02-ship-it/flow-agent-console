# 0.2.63 错误来源与账号误暂停修正

## 查明

`unusual_activity` 是 provider_diagnostics.py 的本地分类键，不是保存的上游原文。分类器检查指定生成 RPC 错误帧中的允许字段，匹配 PUBLIC_ERROR_UNUSUAL_ACTIVITY、unusual activity 或异常活动。仅错误码7不会产生该分类。

历史81cb564d-a978-4532-a618-2346334cc2fb只保存v1分类和结构，不保留原文或匹配标记。因此不能追溯确认当时具体出现哪种文本，也不能声称账号被Google封禁。

## 修正

- v2保留固定允许标记、分类来源、固定响应来源，不保存Cookie、Token、URL参数或原始错误文本。
- 图片、视频提交响应限定同源；视频不再仅按RPC名称匹配任意来源。
- v1分类不再构成账号永久拦截依据。
- 仅确认labs.google响应且含明确PUBLIC_ERROR_UNUSUAL_ACTIVITY标记时，本地冷却30分钟，之后允许重新调度；不自动提交重试，不宣称上游限制已解除。
- 手动暂停策略保留。针对用户本次要求，备份后仅移除先前临时暂停的account_5bce66c57ef3，其他策略和历史记录保持。

## 验证边界

50项本地测试通过，包括本地Chrome错误响应、隐私过滤、旧记录不误禁、冷却到期、队列保护与API/MCP契约。没有向Google提交生成。导致原始生成拒绝的服务端原因不能靠旧v1记录确定，未宣称真实生成已恢复。
